# 포토카드 컬렉션 페이지 만들기

## 이 스킬이 하는 일

`tools/collections.js`에 설정(cfg) 하나를 추가하면 도감 페이지가 통째로 생성된다.
페이지, 사이드바 항목, 홈 카드, 포토카드 전체보기, 위시리스트 연동이 **모두 자동**이다.
엔진은 `tools/collection.js`에 있고, 설정 형식은 그 파일 맨 위 주석에 있다.

## 진행 방식 (중요)

**질문으로 시간을 끌지 말고, 최소 정보만 받아서 페이지를 먼저 만든다.**
없는 값은 아래 기본값으로 채워 넣고, 페이지를 띄워 보여 준 다음 세부 사항을 물어본다.
사용자가 "알아서 해"라고 한 적이 많으므로, 물어보는 건 **꼭 필요한 것 한두 가지**로 줄인다.

### 1단계 — 시작에 필요한 최소 정보

| 항목 | 없으면 |
|---|---|
| 컬렉션 이름 (예: 나랑드 콜라보) | **반드시 물어본다** |
| 카드 종수 · 구성 (멤버별 n종 + 스페셜 n종) | **반드시 물어본다** |
| 구매 방식 (랜덤 뽑기 / 확정 구매 / 둘 다) 과 가격 | **반드시 물어본다** (계산의 핵심) |
| 출시 연월 | 물어보되, 모르면 `ym` 생략하고 나중에 채움 |
| 카드 이름 | 임시로 `원이 1`, `원이 2`… 로 만들고 나중에 교체 |
| 이미지 | 없으면 자리표시자(회색 아이콘)로 만들고 나중에 교체 |
| 수집 난이도 | 일단 3(어려움). 사용자가 직접 정하는 값이라고 안내 |

멤버 5명 기본값(리센느): 원이 `#f286a8`, 제나 `#fca2c4`, 리브 `#76d4c8`, 미나미 `#eec06a`, 메이 `#9ec2f0`

### 2단계 — 설정 추가

`tools/collections.js`의 배열에 cfg 객체를 하나 넣는다. `id`는 영문 소문자+숫자(예: `nrd2026`)로,
사이트 주소 `?tab=<id>`가 되므로 나중에 바꾸지 않는다.

```js
{
  id: 'nrd2026', title: '나랑드 콜라보', year: '2026', ym: '2026-05', diff: 3,
  desc: '한 문장 소개. 홈 카드와 페이지 상단에 같이 쓰인다.',
  parts: '멤버 20종 + 스페셜 5종',              // 생략 가능
  members: [{n:'원이',c:'#f286a8'}, ...],        // 멤버별 분류가 없으면 [] 로 두고 cards의 m 생략
  cards: [
    {n:'원이 1', img:'img/nrd/won1.jpg', m:0},   // m: 멤버 번호(0부터), 없으면 스페셜
    {n:'단체 컷', img:'img/nrd/sp1.jpg', land:true}  // land:true 는 가로형 카드
  ],
  modes: [
    {k:'buy',   label:'제품 구매', price:2000, random:true, hint:'랜덤 1장'},
    {k:'set',   label:'확정 구매', price:9900, hint:'원하는 카드 지정'},
    {k:'trade', label:'교환', price:0},
    {k:'used',  label:'중고 구매', var:true, price:15000}
  ],
  pkg: [], news: []
}
```

**구매 방식(modes)이 이 스킬의 핵심이다.** 제품마다 다르므로 그대로 반영한다.
- `random:true` → 무엇이 나올지 모르는 뽑기형. 이 방식이 있어야 "컴플리트 평균 개수·비용"이 계산된다.
- `price` 고정 금액 / `var:true` 살 때마다 금액 입력(중고 거래 등) / `price:0` 금액 없음(교환, 선물 등)
- `hint` 는 원장 칸 아래 작은 설명.
- 방식은 몇 개든 된다. 예: 확정 구매만 있는 팝업 굿즈 → `[{k:'set',label:'현장 구매',price:5000}]`

칭호는 구성과 구매 방식에서 자동으로 만들어진다(첫 수집 / 절반 / 컴플리트 / 중복 / 방식별 1회·10회 / 평균 비용 초과 / 알뜰 컴플리터).

### 3단계 — 이미지

- 이미지 파일은 `img/<컬렉션id>/` 에 넣고 `cards[].img` 에 상대 경로로 적는다.
- 사용자가 채팅에 올린 이미지는 저장 후 그 경로를 쓴다. 이미지가 없으면 `img` 를 생략한다(자리표시자로 표시됨).

### 4단계 — 빌드 · 확인

```bash
node tools/build.js tools/source.html index.html
```

미리보기(`preview_start` → `http://localhost:8123/?tab=<id>`)로 **반드시 직접 확인한다.**
- 카드 +/− → 구매 방식 선택 창이 뜨고 금액이 맞게 더해지는지
- 저장 버튼, 되돌리기, 기록 로그 수정
- 하트(위시리스트), 카드 크기 슬라이더
- **모바일 폭(375px)** 에서도 확인

### 5단계 — 올리기

```bash
git add -A && git commit -m "<컬렉션 이름> 도감 페이지 추가" && git push origin main
```
배포는 GitHub Pages가 1~2분 안에 반영한다. 주소: `https://scene-simulation.github.io/?tab=<id>`

### 6단계 — 만든 뒤에 물어볼 것

페이지를 보여 주고 나서 아래를 정리해 질문한다. (한 번에 몰아서, 표나 짧은 목록으로)
1. 카드 이름이 실제와 맞는지 / 순서 조정 필요한지
2. 이미지 (없으면 받아서 교체)
3. 출시 연월, 수집 난이도(1~5, 비용과 구하기 어려움 종합)
4. 구매 방식·가격이 정확한지, 빠진 방식은 없는지
5. 패키징 사진, 관련 기사 링크 (주면 토글에 채움)

## 지켜야 할 것

- **다른 페이지 코드를 복사해 새 페이지를 만들지 않는다.** 반드시 엔진(설정 추가) 방식으로 한다.
- CU 405빵 페이지(`tools/source.html`)는 예전에 만든 전용 페이지다. 참고만 하고 건드리지 않는다.
- 저장 키는 `col:<id>` 이므로 `id` 를 바꾸면 사용자 기록이 사라진다. 한 번 정하면 유지한다.
- 사용자에게 보여 줄 때는 **미리보기가 아니라 실제 주소**를 알려 준다. 미리보기 저장 공간은 초기화될 수 있다.
- 테스트로 만든 기록은 끝나고 지운다(`localStorage.removeItem('col:<id>')`).
